# 도라방 만들기: AI 작업 안내

이 폴더에서 일하는 AI(Claude, Codex 등)를 위한 안내다. 선생님과 함께 도름스쿨의 **도라방**(선생님마다 하나인 교실 라이브 방)
안쪽을 꾸미고, 선생님이 좋다고 하면 도름스에 보낸다. 끝까지 읽고 그대로 따른다.

도라방은 도름스쿨 현관의 '라이브 채널'에서 **"@닉네임 쌤의 도라방"**이라는 이름으로 열린다. 선생님은 여기서 라이브 방송을 하고,
회원들은 들어와 앉아서 듣고, 마이크·카메라로 함께 이야기하고, 화면 공유를 보고, 폭죽을 쏘고, 도름네이션을 보낸다.

## 먼저 지킬 것

- **고치는 파일은 `src/room.js` 와 `src/effect.js` 두 개뿐이다.** 나머지 파일은 손대지 않는다.
- 교실 틀(바닥·벽·천장·출입문)은 도름스가 그린다. **안쪽만 꾸민다.** 가로 9m · 세로 7.5m · 높이 3m 를 넘지 않는다.
- 출입문 앞(가로 x 2.9~3.9, 세로 z 2.75~3.75)과 시작 자리((3.4, 2.9) 둘레 0.6m)는 **비워 둔다.** 바닥 깔개(5cm 이하)는 괜찮다.
- 도라방에는 **데이터만** 담긴다(3D 모양과 자리 이름표). 스크립트·소리·바깥 주소·움직임은 넣을 수 없다. 움직이는 연출은
  도름스가 준비한 네 가지(비처럼 내리기 rain · 터지며 퍼지기 burst · 솟아오르기 rise · 빙글 돌기 spin) 가운데 고른다.
- 남의 캐릭터, 상표, 로고를 베낀 모양이나 그림은 만들지 않는다. 선생님이 원하면 이유를 말하고 다른 안을 낸다.
- `DORMS_DORABANG_KEY` 는 비밀번호다. 화면에 출력하거나, 파일(코드, 커밋, README)에 적거나, 캡처에 담지 않는다.
  환경 변수나 `.env` 파일(깃에 안 올라감)로만 둔다. `DORMS_ORIGIN` 은 도름스가 알려 준 주소 그대로 둔다.

## 설문: 선생님께 하나씩 묻는다 (이 순서 그대로, 한 번에 하나만)

질문 하나를 하고 답을 들은 뒤 다음 질문으로 간다. 쉬운 말로 묻고, 선생님이 잘 모르겠다고 하면 추천안을 하나 제시해 고르게 한다.
**아래 항목이 모두 정해지기 전에는 저장·보내기를 하지 않는다.** 항목마다 `src/room.js` 의 어느 값이 정해지는지 함께 적었다.

1. **소개 한 줄**: "도라방을 한 줄로 소개하면요?" (80자 이하) → `intro`
2. **교실 분위기**: 어떤 느낌의 교실인지(예: 아늑한 북카페, 밝은 과학실, 차분한 연수실). 색과 꾸밈을 정한다 → 꾸밈 부품·색
3. **발표 스크린**: 화면 공유가 비치는 판이다. 어느 벽에, 얼마나 크게(너비 1.2~6m, 높이 0.6~3m) → `anchors.screen`
4. **발표자 자리**: 발표하는 선생님이 서는 곳(스크린 가까이) → `anchors.presenter`
5. **MC·부방장 의자 2개**: 진행을 돕는 선생님이 앉는 자리 → `anchors.mcSeats`
6. **청중 좌석**: 몇 석을 어떻게 놓을지(12석 이상 80석 이하, 스크린을 보게). 의자 사이로 걸어 다닐 수 있게 간격을 둔다 → `anchors.seats`
7. **방송 제목 전광판**: 라이브 제목이 흐르는 판(보통 스크린 위) → `anchors.titleBoard`
8. **출석 연출**: 5·20·60분을 머문 선생님이 폭죽을 쏘면 이 자리에서 터진다. 움직임(rain · burst · rise · spin)을 고르고,
   나만의 모양을 쓸지(쓰면 `src/effect.js` 에 작은 모양 하나, 1m 상자 안·면 5천 개 이하) → `anchors.attendance`
9. **도름네이션 연출과 알림판**: 누가 도름네이션을 보내면 연출이 뜨는 자리와 움직임, 보낸 사람이 뜨는 알림판 → `anchors.donation`
10. **조명**: 낮(day) · 저녁(warm) · 밤(night) → `anchors.light`

도름스가 자동으로 갖추는 것(묻지 않는다): 마이크·카메라(도름이 얼굴에 비치기), 말하는 사람 표시, 방장 명패, 부방장 정하기,
내려보내기, 예약 편성표, 대화, 전체 화면 회의 보기, 출석 시각(5·20·60분), 폭죽. 선생님이 물으면 이렇게 안내한다.

## 작업 순서

1. 위 설문을 한 항목씩 진행한다.
2. `src/room.js` 를 고친다. `src/helpers.js` 의 도구(의자 `chair`, 좌석 묶음 `seatGrid`, 벽 판 `wallPanel`, 책상 `desk`,
   책장 `shelf`, 화분 `plant`, 깔개 `rug`, 천장 등 `lamp`, 상자 `box`, 원기둥 `cylinder`)로 만든다. 세 가지를 꼭 지킨다.
   - 기능 판(스크린·전광판·알림판)은 `wallPanel` 로 그리고, 같은 값을 `anchors` 에 넣는다(그림과 이름표가 같은 자리여야 한다).
   - 좌석은 `seatGrid` 나 `chair` 로 의자를 그리고, 앉는 자리 `{ pos: [x, 0, z], yaw }` 를 `anchors.seats` 에 넣는다.
   - 방향 `yaw` 는 0 이면 앞벽(+z) 쪽, `Math.PI` 면 뒷벽(-z) 쪽을 본다. 청중은 스크린을 보게 한다.
3. `npm run preview` 를 실행해 브라우저 미리보기를 띄운다(주소는 터미널에 나온다, 보통 http://127.0.0.1:5240).
   **선생님이 직접 보게 한다.** '걸어보기'로 출입문 안쪽에서 출발해 좌석·발표자 자리까지 걸어가 보고, '위에서 보기'로 배치를,
   '출석 연출 보기'·'도름네이션 연출 보기'로 연출을, 낮·저녁·밤으로 조명을 확인한다. 오른쪽 아래 '기능 자리'가 모두 '있음'인지 본다.
4. 이상한 곳이 있으면 고치고 다시 보여 드린다. 선생님이 **좋다고 말하기 전에는 보내지 않는다.**
5. 선생님이 좋다고 하면 미리보기의 **저장** 단추를 누른다. `dist/` 에 `room.glb` · `preview.webp` · `dorabang.json`
   (나만의 모양이 있으면 `effect.glb`)이 생긴다.
6. `npm run check` 로 검사한다. 도름스 서버와 같은 규칙이다. 실패 줄이 있으면 고치고 3번부터 다시.
7. `npm run send` 로 보낸다. 결과는 도름스 쪽지로 온다(운영자 두 분 중 한 분이 확인한다).
8. `npm run status` 로 상태와 운영자 메모를 볼 수 있다. 고쳐 달라는 답이 오면 메모대로 고치고, 선생님이 다시 확인한 뒤
   `npm run send` 로 다시 보낸다(기다리는 판은 새 판으로 바뀐다).

## 나중에 고치기

- **소개 한 줄 · 방송 도우미(방송을 열 수 있는 선생님, 5명까지) · 연출 움직임**은 도름스 '내 도라방' 화면에서 바로 바꾼다.
- **교실 안쪽(3D)이나 나만의 연출 모양**을 바꾸면 이 폴더에서 고쳐 새 판으로 보낸다. 승인되기 전까지는 지금 판이 그대로 열린다.
